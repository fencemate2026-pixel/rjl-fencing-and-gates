# Website lead bridge

Status: code prepared; automatic import is disabled until production server configuration is completed. Existing Netlify form records and email notifications continue. Enquiries received before activation can be entered manually from those records.

The reserved `submission-created` event handler receives only Netlify-verified submissions. It uses the authoritative host submission ID for idempotency, allowlists fields, removes private uploaded-file URLs, stores a private delivery outbox before sending and retries temporary failures hourly. Invalid records are retained for review; never delete the original Netlify submission as part of delivery. The Supabase endpoint performs its own per-site bearer-key authentication. No key or service-role credential is placed in HTML or browser JavaScript.

Activation requires access to this site's Netlify production environment settings. Generate a separate random32-byte hex token for each brand in a secure environment. Store only its SHA-256 digest in the existing app project's `mtn_sales_source_keys` with the matching brand and enabled=true. In this Netlify project's PRODUCTION context and Functions scope, set `RJL_SALES_INGEST_TOKEN` to that token and `RJL_SALES_ENABLED` to `true`, then redeploy. Leave previews and branch contexts disabled. Never put these values in git, a chat, public files or a build log. Configure both sides and test a clearly labelled internal submission before claiming automatic import is live.

Delivery URL is fixed to the existing RJL maintenance Supabase project. Manual tasks, owner assignment, quote/invoice links, source reports and actual job costing are in its admin-only Sales & Profit workspace. No customer message is sent by this bridge. Review private `rjl-sales-outbox` entries under `review/` in Netlify when the function log reports validation failures. Retry/repair them against the original verified form record. Limit access to authorised RJL administrators and apply the business's retention policy.
